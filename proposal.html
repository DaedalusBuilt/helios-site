The plan I wrote before the capstone started: train a language model entirely from scratch on one computer I own, then put it inside a device people can talk to. No borrowed model, no cloud, no paid services.

High-level goal

A fully self-owned AI that walks on stage on December 8.

Helios is a decoder-only transformer trained entirely from scratch on a single NVIDIA DGX Spark, with no outside base model and no third-party AI. It uses a mixture-of-experts design: only about 1.7 billion of its roughly 8 billion parameters work on any one word, so it trains at the cost of a much smaller model while holding the knowledge of a larger one.

The deliverable is not a file of weights. It is a device: a Raspberry Pi you speak to, which sends your question to Helios and says the answer out loud. Answers are grounded in information looked up at the moment you ask, so the model does the one thing a model this size can do reliably: read real text and answer from it.

Success looks like
  • The model is fully trained, not a big model starved of data
  • Every part is mine: architecture, tokenizer, weights
  • It answers spoken questions on a device, in about 3 to 5 seconds
  • A working demo is guaranteed, with a fallback for every failure (see the risk plan in Research)
The design

Headline specifications

A modern Llama-style transformer, with each feed-forward layer split into 12 experts. A small router picks the best 2 for every word.

PropertyProposed
Total parameters~8 B (mixture-of-experts)
Active per word~1.7 B (top 2 of 12 experts)
Layers / width24 layers, 2,048 wide
Attention16 query heads sharing 4 key/value heads (GQA)
Context4,096 tokens
PartsRoPE, RMSNorm, SwiGLU, weight tying
HardwareNVIDIA DGX Spark, GB10, 122 GB memory
Expected qualityLike a well-trained dense 3 to 4 B model
How mixture-of-experts works

Each layer holds 12 expert networks. For each word, a router turns on just 2 of them. All 12 are stored, but only 2 run, so the cost of training follows the 1.7 B active parameters, not the 8 B total.

One layer, one word: 2 of 12 experts lit.

Why this size

Sized down from 12 B so it could finish.

The first idea was a 12-billion-parameter model. The math said one Spark could only partly train it by December. A fully trained smaller model beats an undertrained larger one, so I cut the parameter count and kept every speed trick.

  • Mixture-of-experts: about 8 B of capacity for the compute of 1.7 B.
  • Ruthless data cleaning: clean, deduplicated text raises quality instead of trading it away.
  • Seed model first: prove the whole pipeline on a ~150 M model before the long run. That small model also becomes the guaranteed fallback demo.
  • Run it 24/7, cooled, with automatic resume, so a weeks-long run can't silently stall.
Data and compute

The numbers the plan rested on

Training compute is about 6 × parameters × tokens. The usual rule for a fully trained model is about 20 tokens for every parameter, counted here by active parameters.

6 N DFLOPs to train N active parameters on D tokens
~20×tokens per parameter for a fully trained model
30–40 Bclean tokens planned, from FineWeb-Edu, Wikipedia and code
1.5–2.5 moof nonstop training planned on the Spark
The data plan: stream an already cleaned open dataset once, turn it into tokens on the fly, and save the token IDs to disk. No web crawling, because the cleaning work is already open source.
